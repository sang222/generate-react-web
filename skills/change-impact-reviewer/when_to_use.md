# When to Use: Change Impact Reviewer

Use this skill when:
- a current brownfield story needs affected and protected scope analysis
- implementation or architecture decisions depend on knowing safe change boundaries
- regression risk must be justified before coding starts

Do not use this skill when:
- the summary of the existing system is missing or too weak
- the task is greenfield and has no baseline to protect

Block when:
- affected or protected modules cannot be identified confidently
- the story likely causes public API or schema break without explicit review
