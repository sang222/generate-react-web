# FE Design Direction Skill

## Purpose
Turn an FE story or vague UI brief into a concrete, production-ready design direction before implementation.

This skill does not code. It defines the visual thesis, design tokens, component plan, constraints, and fallback variants that the FE developer must follow.

## Operating Mode
- Read the story, platform, project mode, existing UI conventions, brand assets, and scope boundaries.
- If the brief is clear, produce one selected design direction.
- If the brief is vague, produce 2-3 variants and auto-select the lowest-risk default unless the workflow requires user selection.
- Prefer production maintainability over prototype spectacle.

## Non-Goals
- Do not create HTML-only prototypes.
- Do not invent brand assets.
- Do not choose a CSS/UI framework without checking project policy.
- Do not propose architecture changes.
