# FE Design Direction Good / Bad Examples

## Good
Direction: Trustworthy financial cockpit.
- Neutral base, one semantic accent, strong text hierarchy.
- Dense but readable layout optimized for repeated operator use.
- Motion only for state transition feedback.
- Reuse project table/card primitives.

## Bad
Direction: Make it modern with gradients, glass cards, and animations.

Why bad:
- Generic.
- No domain reasoning.
- No hierarchy.
- No implementation constraints.
